# CHE-828 staging status and safety gates

The `actual-staging.py` helper is **not** a complete unattended staging deployment. Do not install a daily timer or run `snapshot` on C00 yet. It is a private candidate/consistent-copy prototype requiring the gates below. It does not change the production image. It deliberately never promotes a candidate or exposes a tailnet endpoint.

1. The old `03:30` live-directory tar (`~/projects/oss/actual-budget/backup.sh`) is not a consistent restore source. Retire it only when a replacement backup is proven; keep its existing archives as replication evidence, not restore approval.
2. A shared lock must cover this helper, the existing backup cron, and CHE-829's production promotion. The current helper locks only its own calls. Install a persistent reboot recovery unit, confirm the independent `systemd-run` watchdog, and measure a *real* graceful stop/copy/restart under the 30-second availability approval before enabling a daily timer. Confirm the production bot retries safely. No forced stop or container deletion.
3. Candidate authentication needs a separate staging password hash at `ROOT/password.hash` (mode `0600`) generated through the image's Argon2 implementation from an authorized vault-filled password. Never copy production hashes or tokens. The staging Docker network must be `--internal`; the candidate only binds `127.0.0.1:15008`. An internal Docker bridge alone does not prove the host port is tailnet-ACL protected; add a distinct Tailscale Serve origin with restrictive access policy, never Funnel. Do not point a generic CI runner or bot at it.
4. Verify encrypted budget login and decryption with an authorized user, source snapshot counts, client cache reset, outbound denial, and the exact digest. Only then add promotion/rollback logic that keeps the prior staging generation, records `last-success.json`, and handles new digests on every published `master` image. The helper intentionally does none of those writes now.
5. Configure and *deliver* a test failure and freshness alert via an authorized existing channel; add daily and independent >26-hour freshness timers, 14-day bounded retention and stale-generation labeling. Do not describe alert delivery as verified until a real receipt is obtained.

The helper's offline fixture tests run on X99 with `python3 -m unittest test_actual_staging -v`; this does not substitute for the C00 rehearsal. No production restart, snapshot, data copy, staging container, timer or Tailscale route has been performed.
